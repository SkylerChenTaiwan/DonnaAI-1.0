# 任務建立問題分析報告

**日期**: 2025-01-22  
**報告者**: Claude  
**問題摘要**: 任務建立流程存在三個主要問題

## 問題詳細分析

### 1. 重複的標籤導航問題

**問題描述**: 在 CreateTaskModal 中切換語音/文字輸入時出現重複的標籤導航

**根本原因**:
- CreateTaskModal.tsx 在第 108-128 行設置了導航選項
- TaskForm.tsx 在第 106-135 行也有自己的輸入模式切換標籤
- 當模式為 'form' 時，會同時顯示兩個切換介面

**影響範圍**:
- 使用者體驗混亂，看到兩個功能相同的切換選項
- 介面空間浪費

### 2. 表單輸入缺少適當的 UI 控件

**問題描述**: FormField 組件沒有實現日期選擇器和下拉選單

**根本原因**:
- FormField.tsx 只實現了基本的 TextInput，沒有處理不同的輸入類型
- 在 TaskForm.tsx 中，即使指定了 type="date" 和 type="select"，實際渲染的仍是文字輸入框
- 缺少原生的日期選擇器和下拉選單組件

**影響範圍**:
- 使用者需要手動輸入日期，容易出錯
- 優先級和狀態選擇不直觀
- 整體使用者體驗不佳

### 3. 已排程任務需要時間的驗證錯誤

**問題描述**: 建立任務時出現「已排程任務必須指定時間」的錯誤

**根本原因**:
- 在 CreateTaskModal.tsx 第 71 行，所有任務都被設為 type: 'scheduled'
- 根據 tasks.ts 第 62-64 行的驗證邏輯，scheduled 類型的任務必須有 scheduledAt 時間
- 但是表單中沒有提供 scheduledAt 欄位，只有 dueDate

**影響範圍**:
- 使用者無法成功建立任務
- 系統邏輯不一致

## 解決方案

### 方案 A: 最小化修復（快速修復）

1. **移除重複標籤**:
   - 從 TaskForm 中移除輸入模式切換標籤
   - 保留 CreateTaskModal 中的切換邏輯

2. **修復任務類型**:
   - 將預設任務類型改為 'unscheduled' 或 'pending'
   - 或者根據是否有 dueDate 動態設置任務類型

3. **基本日期輸入**:
   - 暫時保持文字輸入，但加入日期格式提示

**優點**: 快速解決阻塞問題，改動最小  
**缺點**: 使用者體驗仍不理想

### 方案 B: 完整修復（建議方案）

1. **統一輸入模式切換**:
   - 移除 TaskForm 中的輸入模式切換
   - 完全由 CreateTaskModal 控制模式

2. **實現適當的 UI 控件**:
   - 為 FormField 添加日期選擇器支援（使用 React Native DateTimePicker）
   - 實現下拉選單組件（使用 @react-native-picker/picker）
   - 根據 type 屬性渲染不同的輸入組件

3. **修復任務邏輯**:
   - 添加任務類型選擇欄位
   - 根據任務類型顯示/隱藏 scheduledAt 欄位
   - 或者根據輸入自動推斷任務類型

**優點**: 徹底解決問題，提升使用者體驗  
**缺點**: 需要較多開發時間

### 方案 C: 漸進式改進

1. **第一階段**: 修復阻塞問題
   - 修改任務類型為 'pending'
   - 移除 TaskForm 中的重複標籤

2. **第二階段**: 改進 UI 控件
   - 實現日期選擇器
   - 實現下拉選單

3. **第三階段**: 完善任務邏輯
   - 添加任務類型選擇
   - 實現動態表單欄位

**優點**: 平衡開發時間和使用者體驗  
**缺點**: 需要分階段實施

## 建議

建議採用**方案 B（完整修復）**，原因如下：

1. 目前的使用者體驗確實不佳，需要徹底改進
2. 這些都是基礎功能，早期修復可以避免後續更多問題
3. 實現這些 UI 控件後，其他表單也可以重複使用

如果時間緊迫，可以先實施方案 A 的第 2 點（修復任務類型），讓功能可以正常使用，然後再逐步實現其他改進。

## 實施影響評估

- **開發時間**: 方案 A 約 1-2 小時，方案 B 約 4-6 小時
- **測試範圍**: 需要測試任務建立的完整流程
- **相關功能**: 可能影響其他使用 FormField 的表單
- **向後相容**: 需要確保現有任務資料不受影響
