### 🔍 根本原因分析

#### 1. **架構設計衝突**
- **現有系統**: 使用 Stack Navigator 的 `screenOptions` 管理頁面 header
- **新增系統**: ResponsiveLayout + WebNavigator 採用不同的 header 管理策略
- **衝突點**: 組織管理頁面同時使用兩套 header 系統

#### 2. **Layout 元件限制**
- **核心問題**: 現有的 `Layout` 元件不支援 `headerProps` 屬性
- **錯誤假設**: 開發過程中假設 Layout 元件具備 header 管理功能
- **實際狀況**: Layout 元件僅提供基礎佈局容器功能

#### 3. **Web 平台特殊性未考慮**
- **WebNavigator 覆蓋範圍**: 僅覆蓋部分頁面路由
- **組織管理頁面**: 不在 WebNavigator 管理範圍內
- **結果**: 頁面無法享受新的響應式佈局系統優勢
