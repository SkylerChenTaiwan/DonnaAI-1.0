# Web 響應式佈局失敗 - 綜合解決方案

## 1. 問題總結

根據 test-results-analyzer 和 bug-hunter 的分析結果：

### 核心問題
1. **架構設計衝突**：ResponsiveLayout 系統與 Stack Navigator header 管理衝突
2. **Layout 元件假設錯誤**：開發時錯誤假設 Layout 元件支援 `headerProps`
3. **WebNavigator 覆蓋不完整**：管理頁面未納入響應式導航系統
4. **斷點定義不統一**：存在三套不同的響應式系統

### 影響範圍
- 所有管理頁面（OrganizationsScreen、AdminDashboard 等）
- Web 平台的桌面和平板橫向模式
- 96 個 TypeScript 編譯錯誤
- 1,616 個 ESLint 問題

## 2. 解決方案設計

### 方案一：統一響應式架構（推薦）
**目標**：建立統一的響應式佈局系統，解決架構衝突

**實作步驟**：
1. **統一斷點系統**
   - 移除重複的響應式定義
   - 使用 `useResponsiveLayout` 作為唯一來源
   - 更新所有相關元件使用統一的斷點

2. **擴展 WebNavigator**
   - 將所有需要側邊欄的頁面納入 WebNavigator
   - 建立完整的路由映射表
   - 處理導航 header 的顯示邏輯

3. **修復 TypeScript 類型**
   - 解決 Web 平台特定的樣式類型問題
   - 更新 ResponsiveLayout 的類型定義
   - 確保跨平台相容性

### 方案二：漸進式修復
**目標**：快速修復顯示問題，後續重構

**實作步驟**：
1. 直接修改 OrganizationsScreen 使用 ResponsiveLayout
2. 建立臨時的 header 解決方案
3. 標記技術債務，計劃後續重構
