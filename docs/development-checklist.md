# 開發檢查清單

## 必須執行的測試流程

### 每次 PRP 執行前
- [ ] 閱讀並理解所有相關檔案
- [ ] 確認所有依賴函數存在且可用
- [ ] 執行 `npm run web:build` 確認無編譯錯誤

### 開發過程中
- [ ] 每個新功能都要實際測試端到端流程
- [ ] 不要假設任何函數存在，必須檢查
- [ ] 每次引用外部服務函數時，先確認其實作

### 完成 PRP 後
- [ ] 執行完整建置：`npm run web:build`
- [ ] 實際在瀏覽器測試功能
- [ ] 檢查 Console 是否有錯誤
- [ ] 運行相關測試套件（如果存在）

## 常見錯誤防範

### 1. 函數不存在
**問題**: 引用了不存在的函數（如 `importUsersInBatches`）
**預防**: 
- 使用前先 grep 搜尋確認函數存在
- 檢查 import 路徑是否正確
- 查看被引用檔案的實際內容

### 2. Firebase 配置錯誤
**問題**: `db` 實例未正確初始化
**預防**:
- 使用 `getFirebaseDb()` 而非直接引用 `db`
- 確保在使用前已初始化

### 3. 型別不匹配
**問題**: 函數參數或返回值型別不符
**預防**:
- 檢查函數簽名
- 使用 TypeScript 的型別檢查
- 執行建置確認無型別錯誤

## 測試命令快速參考

```bash
# 編譯檢查
npm run web:build

# 開發模式
npm run web

# 型別檢查
npm run type-check

# 測試
npm test

# 清理快取（遇到奇怪問題時）
rm -rf .expo node_modules/.cache
npm run web:build
```

## 教訓總結

這次的問題暴露了我在執行 PRP 時的幾個關鍵缺失：

1. **過度自信** - 沒有驗證基本假設
2. **測試不足** - 只做表面測試，沒有深入測試
3. **缺乏系統性檢查** - 沒有建立標準化的檢查流程

今後必須：
- 每次改動都執行建置檢查
- 實際測試功能而非假設它會工作
- 建立並遵循標準化的開發檢查清單
