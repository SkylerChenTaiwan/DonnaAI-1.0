# DonnaAI Web 元件互動模式與使用流程設計

## 📋 文件概覽

**版本**: 1.0  
**狀態**: PRP-121 互動設計階段  
**更新日期**: 2025-08-18  
**作者**: UX Flow Designer  

### 🎯 設計原則

1. **一致性優先** - 與 React Native 版本保持互動一致性
2. **即時反饋** - 所有操作提供 < 100ms 的視覺反饋
3. **無障礙設計** - 符合 WCAG 2.1 AA 標準
4. **觸控友善** - 最小觸控目標 44px × 44px
5. **鍵盤可達** - 所有功能支援鍵盤操作

## 🎨 第一部分：基礎元件互動模式

### 1. Button 元件互動設計

#### 互動狀態流程圖

```
[初始狀態 (Default)]
    ├─ Mouse Enter / Focus → [Hover 狀態]
    │   ├─ 背景色變淺 10%
    │   ├─ 陰影加深 (0 2px 8px)
    │   └─ 游標變為 pointer
    │
    ├─ Mouse Down / Touch Start → [Pressed 狀態]
    │   ├─ 背景色變深 15%
    │   ├─ 縮放 scale(0.98)
    │   ├─ 陰影內縮 (inset)
    │   └─ 觸覺反饋 (mobile)
    │
    ├─ Loading → [Loading 狀態]
    │   ├─ 顯示旋轉載入圖示
    │   ├─ 文字變為半透明
    │   ├─ 禁用所有互動
    │   └─ 游標變為 not-allowed
    │
    └─ Disabled → [Disabled 狀態]
        ├─ 背景色降至 30% 透明度
        ├─ 文字色降至 50% 透明度
        ├─ 移除所有陰影效果
        └─ 游標變為 not-allowed
```

#### 互動時間軸

```
Timeline (毫秒)
0ms     ─ 用戶觸發動作（點擊/觸摸）
0-50ms  ─ 視覺狀態切換到 Pressed
50ms    ─ 觸覺反饋觸發 (mobile)
150ms   ─ 釋放後恢復到 Hover/Default
300ms   ─ 所有動畫完成
```

#### 變體互動規範

| 變體 | Default | Hover | Pressed | Disabled |
|------|---------|-------|---------|----------|
| **Primary** | 藍色背景 | 藍色+10%亮度 | 藍色-15%亮度 | 灰色30%透明 |
| **Secondary** | 灰色背景 | 灰色+10%亮度 | 灰色-15%亮度 | 灰色20%透明 |
| **Outline** | 透明+邊框 | 背景5%填充 | 背景10%填充 | 邊框30%透明 |
| **Ghost** | 完全透明 | 背景5%填充 | 背景10%填充 | 文字30%透明 |
| **Text** | 無背景 | 下劃線顯示 | 文字變色 | 文字30%透明 |

#### 無障礙支援

```typescript
// 鍵盤互動映射
{
  'Enter': 觸發點擊,
  'Space': 觸發點擊（需防止頁面滾動）,
  'Tab': 聚焦下一個元素,
  'Shift+Tab': 聚焦上一個元素,
  'Escape': 取消當前操作（如在 loading 時）
}

// ARIA 屬性
{
  'aria-pressed': 按鈕按下狀態,
  'aria-disabled': 禁用狀態,
  'aria-busy': 載入狀態,
  'role': 'button'
}
```

### 2. Input 元件互動設計

#### 輸入互動流程

```
[空白狀態]
    ↓ Click/Tap
[聚焦狀態]
    ├─ 顯示藍色邊框 (2px)
    ├─ 標籤上浮動畫 (如有)
    ├─ 顯示鍵盤 (mobile)
    └─ 顯示輸入游標
        ↓ 開始輸入
[輸入中狀態]
    ├─ 即時字數統計
    ├─ 自動完成建議（如有）
    └─ 即時驗證（可選）
        ├─ 有效 → [顯示綠色勾號]
        └─ 無效 → [等待停止輸入]
                    ↓ 停止輸入 500ms
                  [顯示錯誤提示]
                    ├─ 紅色邊框
                    ├─ 錯誤圖示
                    └─ 錯誤文字說明
        ↓ Blur
[驗證狀態]
    ├─ 成功 → [綠色邊框 + 勾號]
    ├─ 警告 → [黃色邊框 + 警告圖示]
    └─ 錯誤 → [紅色邊框 + 錯誤訊息]
```

#### 驗證時機策略

| 驗證類型 | 觸發時機 | 用戶體驗 |
|---------|---------|----------|
| **即時驗證** | 輸入時 | 格式檢查（如 Email） |
| **延遲驗證** | 停止輸入 500ms | 複雜驗證（如用戶名檢查） |
| **失焦驗證** | Input 失去焦點 | 必填檢查 |
| **提交驗證** | 表單提交時 | 最終檢查 |

#### 錯誤恢復設計

```
錯誤狀態恢復流程：
1. 顯示錯誤（紅色邊框 + 訊息）
2. 用戶重新聚焦輸入框
3. 保留錯誤狀態但允許編輯
4. 用戶開始修改
5. 移除錯誤視覺（保留提示文字）
6. 重新驗證後更新狀態
```

### 4. Modal 元件互動設計

#### 開啟/關閉流程

```
[觸發開啟]
    ↓
[背景遮罩淡入] (150ms)
    ↓
[Modal 內容滑入/縮放進入] (200ms)
    ├─ 從下方滑入 (Mobile)
    └─ 中心縮放 (Desktop)
        ↓
[內容可互動狀態]
    ├─ Focus Trap 啟動
    ├─ ESC 鍵監聽啟動
    └─ 背景滾動鎖定
        ↓ 關閉觸發
[Modal 內容滑出/縮放退出] (150ms)
    ↓
[背景遮罩淡出] (100ms)
    ↓
[恢復原頁面狀態]
```

#### 鍵盤導航支援

```typescript
// Modal 內鍵盤導航
{
  'Tab': 在 Modal 內循環焦點,
  'Shift+Tab': 反向循環焦點,
  'Escape': 關閉 Modal（需確認未儲存的更改）,
  'Enter': 確認主要動作,
  'Space': 勾選/取消勾選（在 checkbox 上）
}
```

#### 層級管理

```
Z-index 層級規範：
1000 - 頁面內容
2000 - 下拉選單、工具提示
3000 - Modal 背景遮罩
3100 - Modal 內容
4000 - 確認對話框（在 Modal 上）
5000 - Toast 通知
9999 - 系統級警告
```

### 5. Select 元件互動設計

#### 下拉互動流程

```
[關閉狀態]
    ↓ Click/Tap/Space/Enter
[開啟下拉]
    ├─ 計算最佳顯示位置
    ├─ 展開動畫 (150ms)
    └─ 聚焦到當前選項
        ↓
[選項導航]
    ├─ 滑鼠懸浮 → 高亮選項
    ├─ 上下鍵 → 移動高亮
    ├─ 輸入字母 → 跳到對應選項
    └─ Enter/Click → 選擇選項
        ↓
[關閉下拉]
    ├─ 更新顯示值
    ├─ 觸發 onChange
    └─ 收起動畫 (100ms)
```

#### 搜尋模式

```
搜尋互動流程：
1. 開啟下拉後自動聚焦搜尋框
2. 輸入時即時過濾選項（< 50ms）
3. 顯示匹配數量和無結果提示
4. 支援模糊搜尋和拼音搜尋
5. ESC 清空搜尋，再按關閉下拉
```

## 🚀 第二部分：專業元件使用流程

### 1. NotionTable 互動設計

#### 行內編輯流程

```
[檢視模式]
    ↓ Double Click / Enter
[編輯模式]
    ├─ 單元格變為輸入框
    ├─ 全選當前內容
    ├─ 顯示編輯工具列（如需要）
    └─ 阻止表格滾動
        ↓ 編輯中
    ├─ Tab → 儲存並移到下一格
    ├─ Shift+Tab → 儲存並移到上一格
    ├─ Enter → 儲存並移到下一行
    ├─ Escape → 取消編輯
    └─ Click Outside → 儲存並退出
        ↓
[儲存狀態]
    ├─ 顯示儲存中指示器
    ├─ 樂觀更新（立即顯示）
    └─ 背景同步
        ├─ 成功 → 移除指示器
        └─ 失敗 → 顯示錯誤 + 復原選項
```

#### 排序互動

```
排序操作流程：
1. 點擊列標題 → 顯示排序選單
2. 選擇排序方式：
   - 升序（A→Z, 1→9）
   - 降序（Z→A, 9→1）
   - 自定義排序
3. 顯示排序動畫（行重新排列）
4. 保存排序狀態到 URL/LocalStorage
```

#### 篩選互動

```
篩選器流程：
[新增篩選]
    ↓
[選擇欄位] → [選擇條件] → [輸入值]
    ↓
[即時預覽結果]
    ├─ 顯示符合數量
    └─ 高亮變更
        ↓
[套用篩選]
    ├─ 動畫過渡（淡出不符合的行）
    └─ 更新統計資訊
```

#### 虛擬滾動優化

```
大數據集滾動優化：
- 只渲染可見區域 +- 5 行
- 預載入方向 20 行
- 滾動時顯示行號指示器
- 快速滾動時降低渲染質量
- 停止滾動後恢復完整渲染
```

## 📱 第三部分：表單處理互動模式

### 1. FormField 驗證流程

#### 即時驗證策略

```
[輸入開始]
    ↓
[格式檢查] (即時)
    ├─ Email 格式
    ├─ 電話格式
    ├─ URL 格式
    └─ 數字範圍
        ↓ 停止輸入 500ms
[業務驗證] (延遲)
    ├─ 唯一性檢查
    ├─ 關聯性檢查
    └─ 複雜規則驗證
        ↓ 失去焦點
[完整驗證]
    ├─ 必填檢查
    ├─ 長度檢查
    └─ 自定義驗證
```

#### 錯誤提示設計

```
錯誤提示層級：
1. 欄位級錯誤（紅色邊框 + 底部文字）
2. 區塊級錯誤（區域背景警告色）
3. 表單級錯誤（頂部 Alert）
4. 頁面級錯誤（Modal 對話框）

錯誤恢復指引：
- 明確說明錯誤原因
- 提供修正建議
- 支援一鍵修復（如可能）
- 保留用戶輸入的內容
```

### 2. 表單提交流程

#### 載入狀態管理

```
[提交觸發]
    ↓
[前端驗證] (< 100ms)
    ├─ 失敗 → 滾動到第一個錯誤
    └─ 成功 ↓
[顯示載入]
    ├─ 按鈕變為 loading
    ├─ 表單變為 readonly
    ├─ 顯示進度條（如有）
    └─ 防止重複提交
        ↓
[後端處理]
    ├─ 成功 → [成功反饋]
    │         ├─ 顯示成功 Toast
    │         ├─ 跳轉/關閉
    │         └─ 清空表單（可選）
    └─ 失敗 → [錯誤處理]
              ├─ 顯示錯誤訊息
              ├─ 恢復表單可編輯
              └─ 保留所有輸入
```

### 3. 複雜表單分步驟引導

#### 步驟導航設計

```
[步驟 1] → [步驟 2] → [步驟 3] → [完成]
   ↑           ↑           ↑
   └───────────┴───────────┘
      可返回修改

步驟切換規則：
- 當前步驟驗證通過才能前進
- 可以返回任意已完成步驟
- 顯示每步驟的完成狀態
- 支援步驟間資料依賴
```

#### 進度保存機制

```
自動保存策略：
1. 每個步驟完成時自動保存
2. 重要欄位變更後延遲保存（5秒）
3. 離開頁面前提示保存
4. 支援草稿恢復
5. 顯示最後保存時間
```

### 4. 自動儲存和復原機制

#### 自動儲存流程

```
[欄位變更]
    ↓
[標記為未儲存]
    ↓ 等待 2 秒無操作
[觸發自動儲存]
    ├─ 顯示儲存中指示
    ├─ 保存到 LocalStorage
    └─ 同步到後端（可選）
        ↓
[儲存完成]
    ├─ 更新儲存時間戳
    └─ 清除未儲存標記
```

#### 復原機制

```
復原堆疊管理：
- 最多保留 20 個歷史狀態
- Ctrl/Cmd + Z 復原
- Ctrl/Cmd + Shift + Z 重做
- 顯示可復原的操作描述
- 跨瀏覽器會話保持
```

## 📱 第四部分：響應式互動適配

### 1. 觸控設備手勢支援

#### 手勢識別規範

```
基礎手勢：
- Tap（輕觸）: 主要選擇動作
- Long Press（長按）: 顯示選單 (>500ms)
- Swipe（滑動）: 導航/刪除
- Pinch（捏合）: 縮放內容
- Pan（平移）: 移動視圖

進階手勢：
- Double Tap: 快速編輯/縮放
- Two-finger Tap: 次要操作選單
- Three-finger Swipe: 應用級導航
```

#### 手勢衝突處理

```
衝突解決優先級：
1. 系統手勢（如 iOS 底部上滑）
2. 應用級手勢（如側滑選單）
3. 元件級手勢（如卡片滑動刪除）
4. 內容手勢（如圖片縮放）

防誤觸設計：
- 邊緣 20px 保護區
- 手勢確認閾值
- 取消手勢的逃生路徑
```

### 2. 鍵盤導航完整支援

#### 焦點管理系統

```
焦點順序規則：
1. 從左到右，從上到下
2. 邏輯分組（表單組、導航組等）
3. 重要操作優先
4. Skip Links 支援

焦點樣式：
- 明顯的焦點輪廓（2px 實線）
- 高對比度顏色
- 焦點陷阱處理（Modal、Dropdown）
```

#### 快捷鍵系統

```typescript
// 全域快捷鍵
{
  'Cmd/Ctrl + K': 開啟命令面板,
  'Cmd/Ctrl + /': 顯示快捷鍵幫助,
  'Cmd/Ctrl + S': 儲存當前工作,
  'Cmd/Ctrl + Enter': 提交表單,
  'Escape': 取消當前操作/關閉彈窗
}

// 表格快捷鍵
{
  'Arrow Keys': 單元格導航,
  'Tab/Shift+Tab': 橫向導航,
  'Enter': 編輯單元格,
  'Space': 勾選/取消勾選,
  'Cmd/Ctrl + A': 全選
}
```

### 3. 不同螢幕尺寸互動調整

#### 斷點互動策略

```
螢幕尺寸斷點：
- Mobile: < 768px
  - 單列布局
  - 底部操作列
  - 全螢幕 Modal
  
- Tablet: 768px - 1024px
  - 雙列布局
  - 側邊操作面板
```

## 📊 第六部分：效能優化互動策略

### 1. 載入效能優化

#### 漸進式載入

```
載入優先級：
1. 關鍵路徑內容（< 1秒）
2. 可見區域內容（< 2秒）
3. 互動增強功能（< 3秒）
4. 非關鍵資源（背景載入）

載入指示器策略：
- 0-100ms: 無指示器
- 100-300ms: 微妙指示器
- 300-1000ms: 骨架屏
- >1000ms: 進度條
```

#### 預載策略

```
預載時機：
- 滑鼠懸浮連結（預載頁面）
- 接近滾動邊界（預載內容）
- 空閒時間（預載可能需要的資源）
- 基於使用習慣（智慧預載）
```

### 2. 互動效能優化

#### 防抖與節流

```typescript
// 搜尋輸入防抖（500ms）
const handleSearch = debounce((term) => {
  performSearch(term);
}, 500);

// 滾動事件節流（16ms = 60fps）
const handleScroll = throttle(() => {
  updateScrollPosition();
}, 16);

// 即時儲存防抖（2000ms）
const autoSave = debounce(() => {
  saveToServer();
}, 2000);
```

#### 虛擬化長列表

```
虛擬滾動配置：
- 渲染區域：可見區域 + 上下各 5 項
- 項目高度：固定或動態計算
- 滾動方向：垂直/水平/雙向
- 緩衝區大小：根據效能動態調整
```

### 3. 動畫效能

#### 動畫時長規範

```
動畫時長指南：
- 微小動畫：100-150ms（狀態切換）
- 小型動畫：200-300ms（元素進出）
- 中型動畫：300-400ms（頁面轉換）
- 大型動畫：400-600ms（複雜轉換）

效能優先原則：
- 優先使用 transform 和 opacity
- 避免觸發重排的屬性
- 使用 will-change 提示
- 低端設備降級為無動畫
```
