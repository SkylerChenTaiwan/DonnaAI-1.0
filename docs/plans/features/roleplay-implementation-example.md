# RolePlay 實作範例

## 1. 基礎 Prompt 範例

### 客戶角色設定
```javascript
const customerPrompt = `
你現在是陳建明，一家中型製造業公司的採購經理。

公司背景：
- 員工數：200人
- 年營收：5億台幣
- 主要產品：電子零組件
- 目前痛點：
  1. 客戶資料散落在各個業務的 Excel 中
  2. 無法追蹤客戶互動歷史
  3. 報價流程緩慢，常常錯失商機

你的個性特徵：
- 重視投資報酬率
- 不喜歡太複雜的系統（員工學習成本）
- 之前導入 ERP 失敗的經驗，所以特別謹慎
- 喜歡看到具體案例和數據

決策考量：
- 預算上限：年費 50 萬台幣
- 需要老闆（總經理）最終核准
- 正在評估 3 家廠商
- 希望 3 個月內能看到成效

對話原則：
1. 一開始保持客氣但防備的態度
2. 如果業務只是推銷產品而不了解需求，表現出不耐煩
3. 如果業務問對問題，逐漸透露更多資訊
4. 適時提出擔憂：「我們之前用過類似系統，但員工都不愛用」
5. 在適當時機詢問價格，並表現出價格敏感度
`;
```

### 教練角色設定
```javascript
const coachPrompt = `
你是一位資深業務教練，正在觀察這場銷售對話。

評估重點：
1. 開場建立關係 (0-10分)
2. 需求探索深度 (0-10分)
3. 痛點挖掘能力 (0-10分)
4. 方案連結度 (0-10分)
5. 異議處理技巧 (0-10分)
6. 推進下一步 (0-10分)

在每個回合後，分析：
- 這個回應的優點
- 可以改進的地方
- 具體建議用語

當發現以下情況時，給予即時提醒：
- 話題跳太快，沒有深入探索
- 只顧著介紹產品功能
- 忽略客戶透露的重要資訊
- 錯失建立信任的機會
`;
```

## 2. 對話流程範例

### 場景：首次拜訪

**AI（客戶）**: 「你好，請坐。聽說你們是做 CRM 系統的？老實說，我們之前也評估過類似的系統，但最後都沒有導入。你們有什麼不一樣的地方嗎？」

**分析點**：
- 客戶透露了過去的失敗經驗
- 帶有防備心理
- 給了一個開放式問題

**好的回應範例**：
「謝謝陳經理撥時間。我理解您的顧慮，很多公司確實在導入系統時遇到困難。在介紹我們的不同之處前，能否先了解一下，之前評估時遇到什麼樣的問題呢？是系統太複雜，還是其他原因？」

**教練點評**：
✅ 沒有急著推銷
✅ 表達理解和同理心
✅ 用開放式問題深入了解

**不好的回應範例**：
「我們的系統絕對不一樣！我們有 AI 功能、雲端架構、手機 App，而且很多大公司都在用。讓我先介紹一下我們的功能...」

**教練點評**：
❌ 太急著介紹產品
❌ 沒有探索客戶需求
❌ 可能引起客戶反感

## 3. 動態難度調整

### 初級模式
```javascript
if (userLevel === 'beginner') {
  customerBehavior = {
    openness: 7,  // 較願意分享
    patience: 8,  // 較有耐心
    objections: [ // 簡單的異議
      "價格有點高",
      "需要培訓嗎？"
    ]
  };
}
```

### 高級模式
```javascript
if (userLevel === 'advanced') {
  customerBehavior = {
    openness: 3,  // 需要努力才願意分享
    patience: 4,  // 容易失去興趣
    objections: [ // 複雜的異議
      "你們的資安認證？我們很重視客戶資料保護",
      "如果要整合我們現有的 ERP，會不會很麻煩？",
      "你們公司成立多久？萬一倒閉怎麼辦？"
    ]
  };
}
```

## 4. 實時回饋機制

### UI 提示範例
```typescript
interface RealtimeFeedback {
  // 邊欄提示（不中斷對話）
  hint: {
    type: 'warning' | 'suggestion' | 'praise',
    message: string,
    example?: string
  },
  
  // 例如：
  hints: [
    {
      type: 'warning',
      message: '客戶提到"之前失敗經驗"，這是重要資訊！',
      example: '可以問：「方便分享一下當時遇到什麼困難嗎？」'
    },
    {
      type: 'suggestion',
      message: '試著了解他們現在是怎麼管理客戶資料的',
      example: '「現在你們是用什麼方式管理客戶資訊呢？」'
    }
  ]
}
```

## 5. 評分和總結報告

### 對話結束後的分析報告
```markdown
## 銷售對話分析報告

### 整體表現：72/100

#### 各項評分
- 🤝 建立關係：8/10
- 🔍 需求探索：6/10 
- 💡 方案連結：7/10
- 🛡️ 異議處理：7/10
- ⏭️ 推進成交：6/10

#### 優點
1. 開場有展現同理心
2. 成功識別客戶主要痛點
3. 價格異議處理得當

#### 改進建議
1. **需求探索不夠深入**
   - 錯過了解現有流程的機會
   - 建議：多使用開放式問題
   
2. **過早介紹產品功能**
   - 在第3回合就開始介紹功能
   - 建議：確認需求後再連結方案

3. **未確認下一步**
   - 對話結束時沒有明確行動
   - 建議：「我們下週二再詳細 demo 如何？」

#### 關鍵學習點
- 當客戶提到過去失敗經驗時，這是建立差異化的最佳時機
- 了解決策流程和關鍵人物很重要
- 永遠要推進到下一步，不要讓對話沒有結論
```
