# /error-report 指令設定

## 功能說明
自動產生詳細的錯誤報告，整理問題描述、嘗試過的解決方案、相關程式碼範例，方便詢問其他資深工程師。

## 在 CLAUDE.md 中加入以下設定：

```markdown
### 🔧 自訂指令

#### /error-report - 產生錯誤分析報告
**觸發方式**: 使用者輸入 `/error-report` 或 `/錯誤報告`

**執行步驟**:
1. **收集資訊**：
   - 分析當前對話脈絡，識別主要問題
   - 列出所有嘗試過的解決方案
   - 收集相關的程式碼片段
   - 記錄錯誤訊息和日誌

2. **產生報告**：
   - 建立檔案：`/docs/error-reports/[日期]-[問題簡述].md`
   - 使用以下模板結構

3. **報告模板**：
   ```markdown
   # [問題標題]

   ## 問題描述
   [詳細描述問題現象]

   ## 環境資訊
   - **框架**: [使用的框架和版本]
   - **平台**: [執行平台]
   - **相關套件**: [涉及的套件和版本]
   - **其他**: [其他相關環境資訊]

   ## 問題時間軸
   1. [時間點1]: [發生什麼事]
   2. [時間點2]: [嘗試什麼解決方案]
   3. ...

   ## 錯誤訊息
   ```
   [完整的錯誤訊息或日誌]
   ```

   ## 嘗試過的解決方案

   ### 方案 1: [方案名稱] [✅成功/❌失敗/⚠️部分成功]
   **實作方式**:
   ```[語言]
   [程式碼]
   ```
   **結果**: [執行結果描述]
   **問題**: [遇到的問題]

   ### 方案 2: ...

   ## 相關程式碼

   ### [檔案路徑1]
   ```[語言]
   [相關程式碼片段]
   ```

   ### [檔案路徑2]
   ...

   ## 當前狀況
   - [已完成的工作]
   - [仍存在的問題]
   - [被阻塞的原因]

   ## 需要協助的問題
   1. [具體問題1]
   2. [具體問題2]
   3. ...

   ## 相關資源
   - [相關文件連結]
   - [GitHub issues]
   - [Stack Overflow 討論]

   ## 重現步驟
   1. [步驟1]
   2. [步驟2]
   3. ...

   ## 期望結果 vs 實際結果
   - **期望**: [預期的行為]
   - **實際**: [實際發生的情況]

   ## 附加資訊
   [螢幕截圖說明、開發者工具觀察等]
   ```

4. **自動執行動作**：
   - 分析最近 20-50 則對話訊息
   - 識別技術問題和解決嘗試
   - 提取程式碼片段和錯誤訊息
   - 組織成結構化報告
   - 儲存到 `/docs/error-reports/` 目錄

5. **報告完成後**：
   - 顯示報告路徑給使用者
   - 提供簡短摘要
   - 建議下一步行動

#### 使用範例
```
使用者: /error-report
Assistant: 正在分析對話記錄並產生錯誤報告...

✅ 錯誤報告已產生
📁 檔案位置: /docs/error-reports/2025-01-09-web-icons-display-issue.md

📋 報告摘要:
- 問題: Web 平台圖標顯示為問號
- 嘗試方案: 3 種
- 相關檔案: 15 個
- 建議: 諮詢 React Native Web 專家關於 SVG 渲染問題

你可以將此報告分享給其他工程師以獲得協助。
```

#### 進階選項
- `/error-report brief` - 產生簡短版本（僅包含關鍵資訊）
- `/error-report detailed` - 產生詳細版本（包含完整程式碼和日誌）
- `/error-report [特定問題]` - 針對特定問題產生報告
```

## 實作建議

### 在個人 CLAUDE.md 中加入觸發規則
將以下內容加入 `~/.claude/CLAUDE.md`:

```markdown
## 🔧 錯誤報告產生器
觸發關鍵字: `/error-report` 或 `/錯誤報告`
自動執行: 
1. 分析當前對話中的技術問題
2. 產生結構化錯誤報告
3. 儲存至 ./docs/error-reports/[date]-[issue].md
4. 提供報告摘要和分享建議
```

### 在專案 CLAUDE.md 中加入文件結構
```markdown
### 📁 文件目錄結構
./docs/
├── error-reports/      # 錯誤報告（/error-report 產生）
├── solutions/          # 解決方案文件
├── architecture/       # 架構文件
└── guides/            # 開發指南
```
